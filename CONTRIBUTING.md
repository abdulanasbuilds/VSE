# Contributing to VSE

Thank you for helping make difficult ideas easier to understand.

## Before contributing

Read AGENTS.md, STATE.md, SPEC.md, and docs/QUALITY_AND_PROVENANCE.md. Check the current milestone before introducing a new feature or adding large amounts of material.

## Research contributions

- Prefer primary sources and official datasets.
- Add candidate links to docs/research/SOURCE_CATALOG.md with status and next action.
- Record what was actually reviewed in docs/research/RESEARCH_LOG.md.
- Break wide research tasks into source batches and subject areas.
- Keep a note of unsuccessful searches, missing datasets, dead links, and access restrictions in docs/research/RESEARCH_BACKLOG.md.
- Do not describe a result as independently verified unless an actual verification process was performed and recorded.

## Content contributions

Each topic should explain the learner's question, prerequisite knowledge, main idea, visual model, formal or deeper detail, limitations, and references. Keep claims narrow and cite the sources that directly support them.

Do not use whole copyrighted papers, videos, books, illustrations, or third-party app assets merely because they are online. Record item-specific licences and attribution.

## Visualization contributions

Explain the learning objective, model assumptions, units, parameter ranges, expected behaviour, and failure cases. Include a text fallback, mobile considerations, and a small repeatable test set. Do not use decorative interaction in place of a scientifically meaningful relationship.

## Code and scope

Keep changes focused on the current roadmap milestone. Avoid introducing infrastructure, authentication, monetization, paid services, or dependencies without a documented need. Include commands run and actual results in your handoff.

## Finish with a handoff

Update STATE.md and any relevant backlog/log. A fresh agent should know exactly what changed, what remains, and the next action without guessing.
